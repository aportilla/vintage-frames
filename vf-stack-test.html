direction column row gap system px pad

Top, right, bottom, left. The attribute is emitted in the shortest equivalent CSS shorthand — all four zero leaves it off. Inside a vf-window body leave pad alone: the window already insets 12.

place (per direction) start center end

Where the children sit across the stack, and the only placement it owns. Left off it resolves per direction — start down a column, center across a row, because the two directions want opposite things and always did. (Not align: that is a legacy HTML presentation attribute, which the browser maps to text-align on any element.)

width system px height system px

Both optional — the content governs the box otherwise, a column being as wide as its widest child and a row as tall as its tallest. Declaring one does two things: it is the size half of layout rule 3 (the box is whole by construction, and so is everything filled to it), and along the main axis it is what creates the slack a child's fill-* divides.

Add Up Down Remove Clear fill-width — as wide as the stack allows fill-height — as tall as the stack allows

Each names the outcome, so the stack compiles it to the main axis or the cross axis depending on which way it runs. The cross axis always has a size; the main axis only has slack if you declared one, so a fill along it does nothing until width (row) or height (column) is on. Asked for nothing, a child keeps the size it was drawn at — flex: 0 0 auto, because System 7 boxes don't squeeze.

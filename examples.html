Vintage Frames

Every element in the kit, the parameters it takes, and a live specimen of each state.

Install

npm install vintage-frames
import 'vintage-frames' // registers every <vf-*> element

That is the whole setup — the kit ships no stylesheet. Every visual constant is a --vf-* custom property with an inlined fallback, the bitmap faces register themselves, and vf-desktop paints its own dither, so a component dropped on a blank page renders correctly with no global CSS at all.

The root import registers all 30 elements. To ship less, import by name — same elements, one module each. Those subpaths and the root are the whole export surface; a deeper path fails at resolve time rather than as a 404 in production. 

import 'vintage-frames/vf-button.js'
import 'vintage-frames/vf-checkbox.js'

Sizing takes care of itself

Components are authored in system pixels — the 1-bit art grid — and each one maps a system pixel onto a whole number of device pixels by itself, so the artwork stays crisp at any devicePixelRatio and re-adapts when the window moves to a different display or the reader zooms. No setup, and nesting never compounds it.

So a component's box is never stated in fixed CSS pixels. Windows and dialogs declare their own size in system px — <vf-window width="240" height="176">. Anything else in the demos below is sized in em against the component's own type (on a vf-* host 1em is the kit's 16-pixel face) or as a percentage of its container.

Zoom is followed, in whole steps

Browser zoom moves the target with the reader: the kit renders round(3 × zoom) device pixels per system pixel, so at 200% the art is 6 device px per system px. The steps are the same on every display:

zoomdevice px per system pxsize vs 100%
50–80%267%
90–110%3100%
125%4133%
150–175%5167%
200%6200%
300%9300%
  • The steps nearest 100% hold still — 90% and 110% both round to 3.
  • Ties round up — 150% renders 167% of true size, not 133%.
  • Every engine agrees. Chrome and Firefox report zoom through devicePixelRatio, Safari holds its devicePixelRatio at the hardware and moves the viewport instead; the kit tracks both signals.
  • Pinch-to-zoom is not followed — it magnifies already-rasterized pixels at compositing time. A page that pins --vf-scale opts out of zoom-following too.

One thing is left for the host page, and getting it wrong is what makes an otherwise correct integration look muddy: the device-pixel grid.

Staying on the device-pixel grid

A component is built entirely from whole system pixels, so every edge inside it sits on the grid — but only relative to its own origin. Land that origin, or its size, on a fractional device pixel and the whole 1-bit interior rasterizes wrong: stepped corners staircase asymmetrically, hairline borders and glyph stems smear across two device rows and go gray. The kit handles its own half. Two rules are the page's, and one call covers the first:

  1. State every line-height in whole pixels, and keep padding, margin and gap on integers — or call applyGridSnap() and forget it. Line boxes are the biggest offender: 1.65 × 17px = 28.05px, and every line of prose nudges everything after it further off.
  2. Position a box that contains components from its start edge — or give it a whole-pixel size. Anything right-aligned, centered or sharing space-between computes its origin as edge − width, so a width derived from a text run lands it off the grid. 
import { applyGridSnap, requestGridSnap } from 'vintage-frames'

applyGridSnap()    // every component measures its own paint and cancels the
                   // fractional remainder — returns a cleanup function
requestGridSnap()  // re-run after moving components in a way that resizes nothing

The correction never touches the host's own position, left/top or margin, so it cannot collide with your layout; its whole footprint on your DOM is --vf-snap-dx / --vf-snap-dy on each corrected host. Opt one element out with nosnap. This page calls it — load ?nosnap to turn it off and A/B at 100% zoom. Text set on the kit's own faces has another option: vf-paragraph and vf-label state their line box in whole system pixels themselves.

npm run verify:grid checks every vf-* host at dpr 1/2/3, and npm run verify:snap checks that a page knocked off the grid gets back on it. Point them at your own pages with VF_GRID_PAGES / VF_SNAP_PAGES.

Conventions

What holds across the kit. Everything else is per component.

  • Attributes. Every property is an attribute of the same name in lowercase (cellWidth → cell-width is the only camelCase pair). Booleans are boolean attributes: present means true, so disabled and disabled="false" both disable.
  • Forms. Value-bearing controls are form-associated custom elements: a plain <form> submits them, they appear in form.elements, and form.reset() restores them. name, value, readonly, placeholder, type, min/max/step and required mean what they mean on <input>. Validation is real: reportValidity() blocks with the native message, :invalid matches on the host, and Enter cannot submit past a failing constraint.
  • Disabled blocks interaction, drops the tab stop and honors an ancestor <fieldset disabled>. It dims the label, never the borders or glyphs.
  • Names. <label for>, aria-label/aria-labelledby and aria-describedby on the host all reach the control, bridged inward where its focusable element sits in a shadow root. A control's own label property beats all of them, and <vf-label for> does both jobs at once: click-to-focus and the name.
  • Placement. Nearly every component takes top/left in whole system px and absolutely positions itself within its parent, the unset coordinate 0; set neither and it renders in flow. The exceptions are the owned rows (vf-option, vf-menu-item, vf-list-item, vf-menu) and vf-dialog, whose box the platform owns. A drag writes through the same properties, so read a moved element's position off el.left, not style.left.
  • Roles and keys follow WAI-ARIA 1.2 and the matching APG pattern; each component's table names its own.
  • Events are named vf-* and dispatched bubbles: true, composed: true, so one delegated listener catches them all however deep the shadow roots go. Native events are untouched.
  • Styling. Every visual constant is a custom property (the token table), and each component's internals are reachable through ::part(). 
vf-menu-bar::part(bar) { padding-inline: 24px; }
vf-button::part(button) { min-width: 96px; }
:root { --vf-shadow-offset: 1px; }

One affordance is added rather than reproduced: keyboard access postdates System 7, so the kit draws its own focus mark. Most controls carry it as a 1px dashed rule on the system-pixel grid — inside the control under the ink it marks, or below the whole box where there is no interior to give. The few with no face to draw on, like a window's close box or a list row, keep a dotted ring.

vf-desktop

The gray desktop container: the classic 50% dither, plus window management. A pointerdown or keyboard focus entering a slotted vf-window brings it to front and marks it active, clearing active on the others. DOM order is kept in step with the stacking, so tabbing walks the stack — worth knowing if you style windows by :nth-child. Utility windows live on a floating tier above every document window and stand outside the single-active rule both ways.

Always explicitly sized in system px, never from your stylesheet — the component's own inline size wins. Set the numbers directly or let fitWithin derive them, then position the sized desktop with your own CSS. The windows and icons inside place themselves with their own top/left.

vf-select & vf-option

The popup menu control. Two pointer styles coexist, resolved at the first release: press-drag-release (press the pill, drag onto an item, release to pick) and click-to-open (a quick tap leaves the list open for a second click). Selecting blinks the row ~3 times in ~250ms, then closes.

The panel opens with the selected row over the closed pill, so the label does not move, and the control hugs its widest option, so the value never shifts as the selection changes. Give it a floor with min-width on the host.

A list taller than the screen is clipped, never scrolled — System 7 put no scrollbar on a menu. The edge slot with items beyond it shows a solid arrow instead of a row; rest the pointer on it and the list rolls one row at a time until the arrow runs out. Both edges can overflow at once, and the clamp gives ground a whole row at a time, so even a clipped popup opens with its selected row over the closed pill. A panel that had to slide to fit opens with blank rows at the end the list no longer reaches — the exact travel it rolls through. Set --vf-popup-inset-top once on :root to keep clamped panels clear of a menu bar (24px for a vf-menu-bar).

vf-grid

A lattice of equal cells with 1px rules between them: a tool palette, a color picker's swatch table, a pattern chooser. Switching the pen from solid to dashed changes no layout, and the rules run behind the cells, so an item spanning two cells covers the boundary it swallowed and a cell's own ink is never crossed.

A cell is centered in its well on both axes — a palette usually holds something smaller than the well, a 16px icon in a 26px cell. A cell that means to fill its well asks with place-self: stretch; under collapse that is already the default. Semantics are yours: the grid takes no role, no keyboard behavior and no selection. Put role="group" on the host for a tool palette, role="radiogroup" for a picker, nothing for a plain tiling.

vf-stack

The layout primitive: a flexbox whose gap, pad, width and height are declared in whole system pixels, so a window's insides need no calc(var(--vf-scale, 1) * …) in your stylesheet. It is one of two stylesheet-free ways to lay those insides out; the other is placing each child with its own top/left (see Conventions).

A page's own CSS often cannot say "8 system px". Scaling is per component — each element sets --vf-scale on itself, never on the document — so var(--vf-scale, 1) in your stylesheet resolves only inside a vf-* ancestor. On a plain <div> the fallback 1 wins and the gap comes out 3× too tight, silently.

The content governs the box. A column is as wide as its widest child and a row as tall as its tallest; children keep the size they were drawn at. The stack distributes, never resizes, and shrink-wraps. It paints nothing, takes no role, and returns face, line box, color and selectability to inherit.

vf-label

The static caption: "Name:" beside a field, "Mode" over a radio group, a readout. Chrome type on a 16px line box, stated in whole system pixels, so a column of captions accumulates whole offsets.

for does what a native <label for> does: clicking focuses the target (a focus shortcut, not an activation), and the caption text becomes its accessible name. It never overwrites a name you set, and restores what it found when the label is removed.

vf-icon

The Finder icon. vf-img puts a picture on the grid; this makes it a control — a picture and a caption that select, move and rename together.

The art arrives by slot, one per icon-resource size: large is the 32×32 ICN# and small the 16×16 ics#. size picks which one paints and the cell it paints in. The cell is reserved whether or not there is art filling it — a folder is 32×20 of ink and a document 25×32, and a row of them keeps one baseline because the cell is the unit, not the ink.

open is the Finder's other visual state — the window this icon stands for is on screen — and redraws the art as a ghost: outline held, interior re-filled with the same loose dither the scroll rails use. It costs no second file and no second fetch, and works on cross-origin art.

A name is never abbreviated, and never folded — no ellipsis, no clipping, no wrapping. HFS capped a filename at 31 characters, so the Finder could always draw one in full. Wider than its cell, a name overflows it, centered: width is the cell pitch, not a bound on the name. That also keeps the name crisp, since one run has one width to center. Your side of it is one rule — a declared width must be even, since the component cannot round a number you chose.

Authoring a control on the kit's terms

VfToggleControl is a mixin rather than a base class, so apply it over whichever base your control needs: 

class MyToggle extends VfToggleControl(VfFormControl) {
  @property({ type: Boolean, reflect: true }) override checked = false
  protected override get toggleInternals() { return this.internals }
  protected override get toggleDisabled() { return this.isDisabled }
  protected override activate() {
    this.checked = !this.checked
    this.focus()
    emit(this, 'vf-change', { checked: this.checked })
  }
}

You get the click/Space wiring (including the held-Space auto-repeat guard), one disabled gate every activation passes through, aria-checked/aria-disabled mirroring, and a self-managed host tabindex that never clobbers a consumer's own.
